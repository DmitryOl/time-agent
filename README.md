# Time Agent

Telegram-бот для записи желаний, целей и задач. Проект пока находится на ранней стадии.

## Что работает сейчас

- `/id` — показывает Telegram ID пользователя.
- `/start` — показывает доступные команды допущенному пользователю.
- `/wish текст`, `/goal текст`, `/task текст` — добавляют запись.
- `/list` — показывает последние 10 записей текущего пользователя.
- Записи и журнал действий хранятся в SQLite в Docker volume `agent_data`.
- Доступ пока разрешён **только одному** Telegram ID из `TG_ALLOWED_USER_ID`.
- Резервная копия SQLite создаётся без остановки бота и загружается через
  зашифрованный remote `gdrive_crypt:` в Google Drive.

**Важно:** текущая версия ещё не готова к выдаче доступа нескольким людям.
Не убирайте ограничение `TG_ALLOWED_USER_ID`, пока не внедрены и не проверены
управление пользователями и права администратора.

## Что планируется

1. Автоматический ежедневный бэкап: ручная проверка, затем включение таймера.
2. Управление доступом: заявки, ручное одобрение администратором, отзыв
   доступа с причиной, списки ожидающих, активных и удалённых пользователей.
3. Записи каждого пользователя доступны только ему; администратор может
   просматривать записи выбранного пользователя.
4. При повторном разрешении доступа пользователь сохраняет историю с датами
   и выбирает: продолжить либо начать с пустого активного списка. Старые
   записи при этом архивируются, а не удаляются сразу.
5. Позже — удаление помеченных записей по согласованному сроку хранения.
6. Подключение личного Google Calendar отдельно каждым пользователем.
7. Рекомендации по целям и задачам.

Пункты из этого списка — планы, а не описание уже работающих команд.

## Файлы проекта

- `app/main.py` — код бота.
- `compose.yaml`, `Dockerfile`, `requirements.txt` — запуск приложения.
- `scripts/backup.sh` — резервное копирование и проверка скачанного файла.
- `deploy/systemd/` — исходные файлы расписания; в systemd их нужно
  устанавливать отдельно.
- `.env.example` — перечень переменных приложения без рабочих секретов.
- `.env` — реальные настройки приложения, **не хранится в Git**.
- `rclone.conf` — OAuth-настройки и ключ шифрования резервных копий,
  хранится на сервере вне Git: `/root/.config/rclone/rclone.conf`.

`bash/cp_base.sh` — старый разовый тестовый скрипт на сервере; он не входит
в репозиторий и не нужен для ежедневного запуска.

## Первый запуск на сервере

Инструкция рассчитана на Linux-сервер с установленными Docker Engine,
Docker Compose plugin, Git и rclone. Если их ещё нет, сначала установите
по официальным инструкциям Docker и rclone. Команды ниже выполняются
на **сервере** от пользователя, имеющего доступ к Docker; приведённые
пути бэкапа и systemd рассчитаны на пользователя `root`.

1. Получите код в `/root/apps/time-agent`:

   ```bash
   mkdir -p /root/apps
   cd /root/apps
   git clone АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ time-agent
   cd time-agent
   ```

   Адрес репозитория берётся из настроек вашего Git-хостинга. Если каталог
   проекта уже существует, повторно клонировать его не нужно.

2. Создайте локальный файл настроек:

   ```bash
   cp .env.example .env
   chmod 600 .env
   nano .env
   ```

   Укажите `TG_BOT_TOKEN` (токен Telegram-бота) и
   `TG_ALLOWED_USER_ID` (числовой Telegram ID единственного допущенного
   пользователя). Свой ID можно узнать командой `/id`: она работает и до
   разрешения доступа. `TZ` можно оставить как в образце.

   **Никому не отправляйте `.env` и не добавляйте его в Git.**

3. Соберите и запустите бота:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

   В Telegram отправьте боту `/start`, затем, например, `/wish Проверка`
   и `/list`. При ошибке смотрите журналы:
   `docker compose logs --tail=100 app`. Перед пересылкой журналов
   проверьте, что в них нет конфиденциальных данных.

## Настройка резервного копирования

Нужны установленные на сервере `rclone` и `flock`, а также два настроенных
remote в `rclone.conf`: `gdrive:` (Google Drive) и `gdrive_crypt:`
(шифрование поверх папки `gdrive:time-agent-backups`). Настройку Google
можно провести на компьютере с браузером и затем безопасно передать
`rclone.conf` на сервер. Парольную фразу `crypt` сохраните отдельно:
без неё копии не расшифровать.

На сервере файл должен находиться по пути
`/root/.config/rclone/rclone.conf` и быть доступен только root:

```bash
chmod 700 /root/.config/rclone
chmod 600 /root/.config/rclone/rclone.conf
rclone lsd gdrive_crypt:
```

Не публикуйте содержимое `rclone.conf`. OAuth-токен может обновляться:
поэтому конфигурация rclone остаётся записываемым защищённым файлом,
а не переносится в переменные `.env`. Секреты бэкапа не передаются
контейнеру бота.

Перед включением расписания выполните ручную проверку:

```bash
cd /root/apps/time-agent
./scripts/backup.sh
```

Успешный запуск заканчивается строкой
`Бэкап успешно создан и проверен: ...`. Скрипт создаёт снимок SQLite,
отправляет его через `gdrive_crypt:`, скачивает обратно и побайтово
сравнивает со снимком. Он не удаляет старые копии.

**Только после успешной ручной проверки** установите расписание:

```bash
cp deploy/systemd/time-agent-backup.service /etc/systemd/system/
cp deploy/systemd/time-agent-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now time-agent-backup.timer
systemctl list-timers time-agent-backup.timer
```

Плановое время — ежедневно в 03:30 UTC. `Persistent=true` позволяет
выполнить пропущенный запуск после включения сервера. Проверка последнего
запуска и ошибок:

```bash
systemctl status time-agent-backup.service
journalctl -u time-agent-backup.service -n 100 --no-pager
```

## Обновление через Git

Изменяйте файлы проекта на компьютере, проверяйте изменения и отправляйте
их в Git. На сервере после проверки нужной версии:

```bash
cd /root/apps/time-agent
git status --short
git pull --ff-only
docker compose up -d --build
docker compose ps
```

Не выполняйте `git pull`, если есть неразобранные локальные изменения.
Если менялись файлы в `deploy/systemd/`, дополнительно скопируйте их в
`/etc/systemd/system/` и выполните `systemctl daemon-reload`.
Обновление `.env` выполняется на каждой машине отдельно, не через Git.

## Восстановление и безопасность

Зашифрованные файлы можно просмотреть командой `rclone lsf gdrive_crypt:`.
Для скачивания выбранной копии используйте
`rclone copyto "gdrive_crypt:ИМЯ_КОПИИ" ПУТЬ_К_НОВОМУ_ФАЙЛУ`.
Сначала проверьте скачанный файл; **не подменяйте работающую базу прямо
во время работы бота**. Пошаговую процедуру восстановления в Docker
добавим и проверим отдельно до использования в аварийной ситуации.

Никогда не коммитьте `.env`, `rclone.conf`, SQLite-базы и их копии.
README обновляется вместе с изменениями проекта — в том же коммите
или pull request, а не отдельными устными инструкциями.
